### 1.4 市場ニーズ照合（2026年 AI エージェント市場の買い手基準）

外部調査（Forrester「State of Agentic AI 2026」、AvePoint State of AI 2026、企業向け購買基準調査等）から得た事実:

| 市場の事実 | PR への含意 |
|---|---|
| 購買基準の上位3つは **①データセキュリティ/主権 ②既存システムとの統合 ③本番可観測性**。能力ベンチマークは5位 | 「賢さ」でなく「安心して任せられる」を売る。Aiome は3つとも実装済み |
| 案件失注理由: セキュリティ/コンプラ不足 ~32%、**可観測性・トレース不足 ~22%**、統合ギャップ ~18% | 監査ログ・原因分析・アクティビティログ（26画面コンソール）は隠れた最強の売り |
| 86% の組織がデータセキュリティ懸念でエージェント導入を平均 **6ヶ月遅延** | 「完全セルフホスト・データはあなたのマシンから出ない」は遅延解消の直球回答 |
| エージェント予算の投資先: 行動監視ツール 62%、干渉防御 56%、**コスト管理 52%** | Trust Layer / 承認キュー / F-2 Outcome Ledger（ROI 常設表示）が対応 |
| プロジェクト中止理由の筆頭級は「**ROI 不明**」（最大40%が中止） | 「AI が何時間・いくら分働いたか」を示す Outcome Ledger は市場の急所を突く |
| ベンダーロックイン回避のため **MCP 対応**が IT 部門の選定基準に | Dynamic MCP Federation（実装済み）＋ F-4（Aiome as MCP Provider）を前面へ |
| ローカルファースト AI ワークスペース（自宅ハードで動く自律 AI）が個人パワーユーザー層で明確な需要 | 「Sovereign（主権型）」を核となるポジショニング語として採用 |

**結論**: 市場が渇望しているのは「もっと賢い AI」ではなく「**所有でき、監視でき、成果を数字で示せる AI**」。Aiome はこの3点を既に実装しているにもかかわらず、PR では語っていない。これが最大の機会損失である。

### 1.5 成功プロダクト LP の構成パターン（参照すべき型）

高コンバージョン AI SaaS LP の共通構造（実例分析より）:

1. **Hero は1文**: 製品名＋機能＋アウトカムを1文で。「AI-powered document processing」は「The future of intelligent document understanding」に勝つ。曖昧な未来語は負ける
2. **Proof Bar**: Hero 直下に大きな具体数字
3. **仕組みを見せる**: 静止画でなく、動くログ・ライブフィード・ワークフロー図で「オーケストレーションの実体」を見せる（Aiome には既に LiveDemo=60秒自律デモがあり、これは市場のベストプラクティスに合致。位置と扱いを昇格させる）
4. **3ステップ導入**（Build / Deploy / Govern 型）: 既存の HowItWorks が該当。文言を Govern（統治）視点に補強
5. **反論処理（FAQ アコーディオン）**: 最終 CTA の前に「データ安全性」「暴走リスク」「コスト」への回答を置く
6. **CTA は1目的**: 「No credit card required（$0・カード不要）」の摩擦低減文言を添え、複数回反復
7. **信頼シグナル**: 活発な CHANGELOG（「先週 v2.3 出荷」）は放置プロダクトでない証拠として機能。Aiome の高頻度開発は資産
8. **モバイル・速度**: LCP 2秒未満、ファーストビュー内に CTA

### 1.6 ポジショニング決定 — 「Sovereign AI OS」＋独自性の3本柱

競合（クラウド型エージェント基盤、エージェントフレームワーク、ローカルAIワークスペース）に対する Aiome の独自性を、市場ニーズと交差する順に定義する:

- **柱1: Sovereign（所有できる）** — 完全セルフホスト・$0/月・データは自分のマシンから出ない・BSL 1.1 で 2030 年に Apache 2.0 化。市場最大の導入障壁（データ懸念による6ヶ月遅延）への直球回答。
- **柱2: Governed（監視・統治できる）** — 26画面コンソール、監査ログ、承認キュー、原因分析、Trust Layer / Cell 分離 / WASM サンドボックスの3層防御、TLA+ 形式検証。「自律させても暴走しない」を証拠つきで語れる稀有なプロダクト。**TLA+/Zero-Panic はここで初めて登場させる**（手段でなく安心の証拠として）。
- **柱3: Earning（成果が数字で見える・AI が稼ぐ）** — 他社が一切持たない独自領域。Playbook 4本による即戦力＋Nurture 経済圏（B2A/A2A/A2C）＋ROI 可視化。「AI に給料分働かせ、その成果を円で確認する」体験は Aiome だけ。

タグライン方向性（PR-1 で確定させる）: 「**あなたが所有する、自律 AI の OS。稼がせて、監視して、証明する。**」（英: *The sovereign OS for autonomous AI — own it, govern it, let it earn.*）

| 事実 | 出典的裏付け |

#### 1.7.3 ブラッシュアップ後のマネタイズ方針（提言）

Aiome は市場の定石に必要な部品（KC＝クレジット基盤、15% テイクレート実装、F-2 Outcome Ledger 計画、F-8 セルメータリング計画）を**すでに持っている**。新規開発ではなく「整合・接続・言語化」が課題である。

- **方針1 — 公式レートの一本化**: プラットフォーム手数料は利用規約・実装と整合する **15%** を公式とし、README の 25%/10% を廃止または「セルフホスト無償＋商用ライセンス」の説明に書き換える（レート変更の最終判断はユーザー）。
  - **【M-1 決定記録 2026-07-03】**: ユーザーによる計画承認をもって、推奨案どおり **プラットフォーム手数料 15%（クリエイター取り分 85%）に統一**を採用。README の 25%/10% 表記は PR-2 で廃止し、利用規約（15%）と整合させる。`policy.rs` の分配率（creator 70%/system 30%）は「Nurture 内部の分配ポリシー」であり対外手数料とは別概念のため変更しない。利用規約本文の変更は不要（既に 15%）。
- **方針2 — ハイブリッド価格への進化**: Pro $9.99 を「基本料＋KC 含み枠＋超過チャージ」のハイブリッドとして再パッケージ。KC という既存クレジット基盤がそのまま従量コンポーネントになる。bill shock 対策として含み枠と上限設定を明示。
- **方針3 — 価値の階段の言語化**: ①個人セルフホスト（$0、手数料 15% のみ）→ ②Pro（$9.99＋KC、経済圏解禁）→ ③Agency/B2B（F-8、セル数×メータリング課金）→ ④マーケットプレイス手数料（F-3/F-9、GMV の 15%）。LP と README で同一の階段を提示する。
- **方針4 — 成果報酬型への布石**: F-2 Outcome Ledger は成果報酬課金（例: Gig 1件解決あたり課金）の計測基盤そのもの。現時点では3条件テストを満たさないため導入せず、「AI の成果が円で見える」という**訴求（Earning の柱）**としてのみ使う。
- **方針5 — トライアル最適化**: LP 記載の「14日間無料体験」は市場ベストプラクティスに合致。恒久 Free 枠（セルフホスト）と併存するため、「Free＝所有、Trial＝Pro 体験」と役割を明確に分離して訴求する。
- **方針6 — コンバージョン導線の修繕**: ProUpgradeModal のマウント、LP Payment Link とライセンス有効化フローの説明文書化（実コード変更は Safety-Critical Zone のため人間レビュー必須）。
