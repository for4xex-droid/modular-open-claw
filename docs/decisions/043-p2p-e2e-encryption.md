# ADR-043: P2P Federation エンドツーエンド (E2E) 暗号化

## Status
Accepted

## Context
現在、P2P連邦ネットワーク（`biome.rs` などを通じたノード間通信）において、メッセージやアセットデータはトランスポート層の暗号化（TLS）のみで保護されています。しかし、通信メッセージは中継用のハブ（Samsara Hubなど）を経由することがあり、中継ノードが妥協された場合や、悪意ある中継者によってメッセージ本文が傍受・解読されるリスク（中間者攻撃、SSRFの副次的影響など）があります。
これに対処するため、送信元から受信先の間で直接メッセージペイロードを保護するエンドツーエンド（E2E）暗号化メカニズムを設計する必要があります。

## Decision / Implementation Details
1. **ハイブリッド暗号アルゴリズムの採用**:
   - **非対称鍵共有**: X25519 (Diffie-Hellman over Curve25519) を使用して、ピア間で安全に共有秘密（Shared Secret）を確立します。Ed25519 署名用鍵（シードおよび公開鍵）から X25519 鍵ペアへ Montgomery 変換を行うことで、追加のハンドシェイクなしに即座に共有秘密を導出可能な 0-RTT/1-RTT 方式を採用。
   - **鍵導出**: HKDF-SHA256 を用いて、共有秘密から対称暗号用のセッションキー（Session Key）とソルトを導出します。
   - **対称暗号**: 対称鍵暗号には `ChaCha20-Poly1305` (AEAD) を使用し、機密性と完全性の両方を担保します。

2. **鍵管理**:
   - 各ノードは `Sovereign Verifier` およびセキュアストア（`AbyssVault` など）によって保護された自身のアイデンティティ鍵（Ed25519 鍵ペア）を保持し、これに基づき Montgomery 変換を通じて X25519 鍵を導出します。
   - 暗号化メッセージのペイロードは、一時的な送信元公開鍵 (Ephemeral Public Key: 32 bytes) + 初期化ベクトル (Nonce: 12 bytes) + 暗号文 (Ciphertext) を連結し、Base64 でエンコードして伝送します。

3. **ペイロード構造および署名検証バグの修正**:
   - `encryption` フィールドの値を `"none"` から `"x25519-chacha20poly1305"` に更新。
   - 中継ハブ（Samsara Hub）が暗号化されたメッセージを配送する際、Unicode サニタイズや CSAM フィルターによる平文バイナリの破損を防ぐため、`encryption != "none"` の場合はサニタイズ処理をスキップするよう改修。
   - 送信側とハブ間で署名検証の不一致が発生する問題を解決するため、署名対象ペイロードの順序を双方で `{sender_pubkey}:{topic_id}:{content}:{clock}` （`content` は Base64 化された E2E 暗号文）に統一。

## Consequences
- **利点**: 中継サーバー（Samsara Hub等）やネットワーク中継路の安全性が保証されない環境下であっても、データの絶対的な機密性が保証されます。
- **トレードオフ**: 各メッセージ送受信時に暗号化・復号のCPUコストが発生します。
