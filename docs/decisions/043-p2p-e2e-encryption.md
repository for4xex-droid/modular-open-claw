# ADR-043: P2P Federation エンドツーエンド (E2E) 暗号化

## Status
Proposed

## Context
現在、P2P連邦ネットワーク（`biome.rs` などを通じたノード間通信）において、メッセージやアセットデータはトランスポート層の暗号化（TLS）のみで保護されています。しかし、通信メッセージは中継用のハブ（Samsara Hubなど）を経由することがあり、中継ノードが妥協された場合や、悪意ある中継者によってメッセージ本文が傍受・解読されるリスク（中間者攻撃、SSRFの副次的影響など）があります。
これに対処するため、送信元から受信先の間で直接メッセージペイロードを保護するエンドツーエンド（E2E）暗号化メカニズムを設計する必要があります。

## Proposed Design
1. **ハイブリッド暗号アルゴリズムの採用**:
   - **非対称鍵共有**: X25519 (Diffie-Hellman over Curve25519) を使用して、ピア間で安全に一時的な共有秘密（Shared Secret）を確立します。
   - **鍵導出**: HKDF-SHA256 を用いて、共有秘密から対称暗号用のセッションキー（Session Key）とソルトを導出します。
   - **対称暗号**: 対称鍵暗号には AES-256-GCM（または ChaCha20-Poly1305）を使用し、認証付き暗号化（AEAD）により機密性と完全性の両方を担保します。

2. **鍵管理とハンドシェイク**:
   - 各ノードは `Sovereign Verifier` およびセキュアストア（`AbyssVault` など）によって保護された自身のアイデンティティ鍵（X25519 鍵ペア）を保持します。
   - ノード間の通信開始時に、一時的な（Ephemral）X25519 鍵ペアを生成して Diffie-Hellman ハンドシェイクを実行し、前方秘匿性（Forward Secrecy）を確保します。
   - 公開鍵はピアの証明書またはSovereign Verifierによって署名され、なりすましを防止します。

3. **ペイロード構造**:
   - `encryption` フィールドの値を `"none"` から `"x25519-aes256gcm"` に更新します。
   - メッセージのボディ部分（Payload）を暗号化し、Base64（またはバイナリのオクテットストリーム）でシリアライズします。暗号化されたペイロードには、暗号化に使用した一時公開鍵（Ephemeral Public Key）と初期化ベクトル（IV/Nonce）を添付します。

## Consequences
- **利点**: 中継サーバー（Samsara Hub等）やネットワーク中継路の安全性が保証されない環境下であっても、データの絶対的な機密性が保証されます。
- **トレードオフ**: 各メッセージ送受信時に暗号化・復号のCPUコストが発生し、接続初期化時にハンドシェイク用のオーバーヘッド（1往復）が加わります。
