# 2026-03-18 - Soul Engine (Phase 1) 実装とディープスキャン

## 実施事項
- **Soul Engine 基盤実装**: `libs/soul` クレートを新規作成。`AgentSoul` (核), `PredictiveModel` (L2/可塑性), `SomaticMarker` (L1/反応), `Instinct` (L3/元認知) のデータ構造と基本ロジックを実装。
- **永続化層の実装**: `SqliteSoulStore` を `infrastructure` に追加。SQLite への JSON シリアライズ保存、10,000件の `experience_buffer` 制限（I-2）を実装。
- **第1回ディープスキャン修正**: 10件の問題（C-1, I-1〜I-5, R-1〜R-4）を修正。`compute_hash()` による状態整合性保証、テスト強化、安全属性の付与など。
- **第2回ディープスキャン修正**: 6件の問題（I-6〜I-9, R-5〜R-6）を修正。`AgentSoul::new` ファクトリ、`samsara-hub` のカラム追加、エラー変換トレイト、値のクランプ処理を実装。
- **連邦同期（Federation）の拡張**: `FederatedKarma` に人格メタデータ（generation, somatic_valence）を追加し、ハブ経由での人格進化の共有を可能にした。

## 意思決定
- `soul_mutator` (旧系/ファイルベース) と `AgentSoul` (新系/DBベース) の二重管理については、Phase 2 で `SamsaraEngine` への統合を進める方針とし、ドキュメントに明記した。
- `experience_buffer` は際限なく肥大化するため、インフラ層で 10,000 件に制限する。

## 次のステップ
- **SamsaraEngine 実装 (Phase 2)**: 転生 (Rebirth) と蒸留 (Distillation) のプロンプトエンジニアリングおよび LLM 連携ロジックの実装。
- **ドメインアダプター実装**: `api-server` 用の具体的な `SoulDomainAdapter` を作成し、実際の経験を魂に蓄積可能な状態にする。
