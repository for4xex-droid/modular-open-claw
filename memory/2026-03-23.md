### 1. Autonomous Demo — SQLite `database is locked` 修正 ✅

**問題:** Phase 25 で実装した Autonomous AI Economy Demo が Step 5〜7 で `database is locked (SQLITE_BUSY, code 517)` エラーにより停止。

**根本原因（3層構造）:**

| レイヤー | 原因 | 影響 |
|---|---|---|
| **gig_engine トランザクション** | `accept_bid()`, `deliver()`, `verify_and_settle()` が `pool.begin()` で排他ライターロックを取得 | コネクション長時間保持 |
| **audit trigger 連鎖** | INSERT/UPDATE トリガーが `audit_ledger_global` への INSERT を発火 | ロック保持時間延長 |
| **SSE 多タブ飽和** | ブラウザ9タブ × 5秒ごとDB SELECT → `max_connections=10` プール枯渇 | トランザクションがコネクション取得不能 |

**修正内容:**
- `apps/api-server/src/autonomous_demo.rs` を**全面書き換え**
  - gig_engine の trait メソッド呼び出しを完全排除
  - 全DB操作を**個別SQLクエリ**で直接実行（トランザクション完全排除）
  - 各クエリ間に 100ms sleep でコネクション即時解放を保証
  - audit trigger はデモ前に DROP、デモ後に CREATE（エラー時も復元保証）

**検証結果:**
- Step 0→8 全ステップ完走確認（`database is locked` エラーなし）
- Resonance Buffer: 30µ 蓄積
- Agent A: Lv1 → Lv2 進化
- `cargo test --workspace` 全テストパス

## ⚠️ 本番運用に向けた未解決課題（ADR-014 に詳述）

今回のデモ修正は**デモ専用**の対応。本番運用には以下が必要:

| 施策 | 優先度 | 概要 |
|---|---|---|
| **PostgreSQL 移行** | P0 | SQLite の単一ライター制約がマルチユーザーで致命的。`sqlx` 使用のため移行コスト中程度 |
| **非同期 Audit Logging** | P1 | トリガー同期 INSERT → アプリ層キュー経由の非同期記録に変更 |
| **SSE 接続共有** | P2 | SharedWorker で複数タブが1つの SSE を共有、またはサーバー側で同時SSE数制限 |
| **コネクションプール増強** | P2 | `max_connections` を20以上に（PostgreSQL 移行後に効果発揮） |

**注意:** `autonomous_demo.rs` はインラインSQL。`gig_engine.rs` のスキーマ変更時は手動更新が必要（デュアルメンテナンス）。
