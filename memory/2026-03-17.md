# 2026-03-17 - セキュリティ強化と基盤リファクタリング

## 実施事項
- **Key-Proxy 認証基盤刷新**: `VAULT_SECRET` を `AppState` 移行し、起動時に環境変数を消去（Wipe）する実装を完了。定数時間比較（ConstantTimeEq）によりタイミング攻撃を防御。
- **api-server / samsara-hub 堅牢化**: 起動時の `expect()` を排除し、適切なエラーログと `process::exit(1)` に移行。`API_SERVER_SECRET` 等の秘密情報を `AppState` で一括管理。
- **WASM サンドボックス脆弱性修正**: `host_write` および `fs_reader` におけるパス判定を、文字列前方一致から `Path::starts_with` に変更。`/mnt/workspace_backup` 等のパストラバーサルバイパスを完全に遮断。
- **Docker 設定修正**: `key-proxy` の `BIND_ALL=true`（全インターフェース待受）を削除。`nurture` 環境の `FEDERATION_SECRET` 同期。
- **api-server 認証ガード強化**: クエリパラメータによる `token` 認証を廃止（ログ漏洩防止）。`Authenticated` エクストラクターを `AppState` 参照に移行。

## 意思決定
- 秘密情報は起動時に一度だけロードし、その後環境変数から消去することで、プロセスダンプや子プロセスへの漏洩リスクを最小化する。
- 署名バイパス脆弱性について全6箇所（samsara-hub, api-server, federation.rs）を再スキャンし、既に `if let Ok` 等で適切にハンドリングされていることを確認。

## 2026-03-17 18:00 追加事項
- **BastionGuard ホワイトリスト検証 (H-6)**: 従来のブラックリスト判定を廃止し、`PathSandbox` による厳格なパス検証を実装。コマンド引数の正規化によりパストラバーサルを構造的に遮断。
- **DB Migration 安全性向上**: `migrations.rs` におけるサイレントなエラー無視を排除し、構造化された `warn!` ログと例外フィルタリングを導入。
- **秘密情報ライフサイクル管理**: `api-server` および `samsara-hub` で `FEDERATION_SECRET` を `AppState` 移行し、起動直後に環境変数から抹消 (`remove_var`) する「Abyss Vault」パターンの適用範囲を拡大。
- **統合テスト修復**: 秘密情報管理の刷新に伴い、`api_integration_tests.rs` を `AppState` ベースに更新し、全ビルドが通ることを確認。
