# データベースマイグレーション戦略

## 1. 概要
本プロジェクトでは、開発初期の機敏性と本番環境のスケーラビリティを両立させるため、`sqlx` を用いたデータベース抽象化戦略を採用しています。

## 2. 段階的移行パス

### Phase 1: SQLite (現在)
- **用途**: ローカル開発、単体テスト、初期α版。
- **設定**: WAL (Write-Ahead Logging) モードを有効化し、読み取りの並行性を確保。
- **利点**: ゼロコンフィギュレーション、ファイルベースで高速。

### Phase 2: PostgreSQL (本番)
- **用途**: 商用サービス、マルチノードデプロイ。
- **設定**: Isolation Level = `SERIALIZABLE`。
- **利点**: 高い書き込みスループット、厳格なデータ整合性、水平スケーリング。

## 3. 実装上の工夫
- `sqlx` の `Runtime` と `Pool` を介して、ドライバの差異を吸収。
- SQL 構文は極力標準 SQL に準拠。差異（例: UPSERT）については、ドライバごとに切り替えるマクロまたはヘルパー関数を準備。
- マイグレーションファイルは `sqlx-data.json` により、データベースの実体なしでもオフラインビルド・検証が可能。
