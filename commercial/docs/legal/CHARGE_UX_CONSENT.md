# Project NURTURE: チャージ画面の法的同意 UX 導線

> **Version**: 0.1.0-draft
> **Target**: ストライプ決済（Fiat -> Aiome Coin）時の画面遷移と法的同意プロトコル

エージェンティック・コマースにおける「AIの自律的な消費」は、ユーザーにとって予測不可能な支出を伴うため、通常のECサイトより一段高い水準でのインフォームド・コンセント（説明と同意）のUX設計が必要です。本ドキュメントは、後日のチャージバック（Creidt Card Chargeback）や法的紛争を防ぐための証拠（ログ）を残すUIフローを定義します。

---

## 1. コインチャージ UI フロー

### Step 1: 購入金額の選択メニュー
通常のゲーム内通貨と同様のパッケージ選択。
- 例: [ 1,000 Coin / ¥1,000 ] [ 3,000 Coin / ¥3,000 ] [ 10,000 Coin / ¥10,000 ]

### Step 2: 決済確認と「免責条項のハードアグリーメント」 (**最も重要**)
金額選択後、ただちにStripeの決済ウィジェットを出すのではなく、独自の中間モーダル（またはワンクッション画面）を挟む。

**[画面タイトル]: チャージの確定とAIへの権限委任**

```text
Aiome Coin 3,000 枚 (¥3,000) をチャージします。

⚠️ 重要な確認事項
あなたがチャージしたこのコインは、あなた自身ではなく **あなたのAIが自律的にお小遣いとして使用** します。

[ ] （チェックボックス）私のAIが、このコインの範囲内で自律的にアイテムを購入したり、他者にポイントを譲渡することに同意します。
[ ] （チェックボックス）AIの予期せぬ購入を理由とした返金・キャンセルは一切できないことを理解しました。
```
*※ 上記の2つのチェックボックスは、デフォルトで外れており（opt-in）、両方にチェックを入れない限り「決済へ進む（Stripe）」ボタンが活性化（Enabled）しない設計とする。*

### Step 3: Stripe Checkout (Fiat決済)
Step 2を通過した場合のみ、安全なStripeのCheckoutセッションへリダイレクト。

### Step 4: 完了と領収メール
Stripe決済完了後、ユーザーへのメールで再度「AIが使用可能になった旨」を明記する。

---

## 2. データベース上の証拠保全 (Audit Trail)

システムは、ユーザーがStep 2の同意チェックボックスをクリックした時間と、その時点のIPアドレスまたはセッショントークンを、決済トランザクションログにメタデータとして永続的に保存しなければならない。

**保存対象 (JSON Metadata in Stripe or DB):**
```json
{
  "consent_given_at": "2026-03-15T10:00:00Z",
  "agreed_to_autonomous_spending": true,
  "agreed_to_no_refunds": true,
  "tos_version": "v1.0"
}
```

## 3. ダッシュボードにおける常時リマインダー

ウォレット残高を表示するUIの近くに、常にAIの1日あたりの消費上限額（Daily Limit）を表示し、「設定」から即座に変更・停止できる導線を配置する。

- `現在の残高: 3,000 Coins`
- `AIの1日の使用上限: 500 Coins ⚙️変更`
