# ADR-003: Typestate パターンの採用

## ステータス
Accepted

## コンテキスト
トランザクションの状態遷移（Initiated → Authorized → Settled）を、ランタイムの `if` 文チェックに頼らずに保証したい。

## 決定
Rust の型システムを用いた Typestate パターンを採用する。

## 理由
1. **コンパイル時保証** — Authorization を経ていない入金（Settlement）処理を記述すると、コンパイルエラーになる。
2. **ランタイム負荷ゼロ** — 型情報のみを用いた制約であり、バイナリサイズや実行速度に影響を与えない。
3. **自己文書化** — 関数シグネチャ `fn settle(tx: Transaction<Authorized>)` を見るだけで、実行条件が明確。

## 影響
- ジェネリクスの多用により、コンパイル時間がわずかに増加する。
- 状態遷移のラッパーメソッドを定義するボイラープレートが必要。
