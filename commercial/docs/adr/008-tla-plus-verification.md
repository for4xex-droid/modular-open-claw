# ADR-008: TLA+ 形式検証の採用

## ステータス
Accepted

## コンテキスト
決済プロトコルの不変条件（二重支払いがない、合計残高が変化しないなど）を、テストの実行漏れなく数学的に証明したい。

## 決定
TLA+ を用いてプロトコルのモデルを作成し、TLC モデルチェッカーによる全探索検証を実施する。

## 理由
1. **バグの早期発見** — 並行処理下での稀な競合状態（Edge Case）は、通常の単体テストではまず検出できない。
2. **設計の明文化** — 曖昧な自然言語ではなく、数学的仕様としてプロトコルを定義することで、AI によるコード生成の精度も高まる。
3. **信頼性のアピール** — 「数学的に検証済みである」ことは、セキュリティ DD において最強の武器になる。

## 影響
- TLA+ の学習と仕様の保守コストが発生する。
- 形式仕様と Rust 実装の間の同期を手動で（またはプロパティベーステストで）保つ必要がある。
