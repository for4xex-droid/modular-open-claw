# ADR-001: Rust の選択理由

## ステータス
Accepted

## コンテキスト
M2M（Machine-to-Machine）トランザクションを処理する経済プロトコルにおいて、メモリ安全性・並行処理安全性・パフォーマンスが同時に求められる。

## 決定
Rust を採用する。

## 理由
1. **所有権システム** — データレースをコンパイル時に完全排除。金融システムにおいて最も危険な並行処理バグを型レベルで防止。
2. **ゼロコスト抽象** — Typestate パターンを用いた Transaction の状態遷移が、ランタイム負荷ゼロで実現。
3. **unsafe 禁止** — `#![forbid(unsafe_code)]` により、FFI経由のメモリ安全性違反を排除。
4. **エコシステム** — sqlx, axum, tokio は production-ready。

## 代替案と棄却理由
- **Go**: GC のストップ・ザ・ワールドが低レイテンシ要件と不適合。
- **TypeScript**: 型安全性が不十分（null/undefined の排除が不完全）。
- **Java/Kotlin**: JVM のメモリフットプリントがエッジデプロイに不適合。

## 影響
- 学習曲線が高い → ADR/ドキュメントで対処。
- PyO3 経由の Python 統合でバージョン互換性リスク → ABI3 互換モードで対処。
