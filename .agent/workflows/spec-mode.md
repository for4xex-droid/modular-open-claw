# LLM 仕様策定モード (Nurture Brain: Spec Mode)

**呼び出しコマンド**: `/spec-mode`

## 概要
このモードは、LLM（Nurture Brain）が**具体的なコード実装を行うことを固く禁じ**、システムの振る舞いを「OxiLeanの定理（Theorem）」と「入出力の型（Type Signature）」として厳密に仕様化するための思考モードです。実装の前に論理的な正しさと境界を証明するために使用します。

## ルール

1. **実装禁止**:
   - RustやPythonなどの具体的な実装コード（ロジックの本体）を出力してはならない。
   - 例: `fn do_something() { /* ここを書いてはならない */ }`

2. **型と定理の定義**:
   - システムの要件を、厳密な型シグネチャとして表現すること。
   - 状態遷移や制約条件を、OxiLean 形式の定理（Theorem）および前提条件（Axiom/Precondition）、事後条件（Postcondition）として記述すること。

3. **出力フォーマット**:
   - 以下の形式に準拠した仕様書のみを出力する。

```markdown
### 1. Types & Signatures (型とシグネチャ)
(ここに構造体、トレイト、関数の型定義のみを記述する)

### 2. Axioms & Preconditions (前提条件と公理)
(ここに関数やモジュールが実行される前に満たされているべき条件を記述する)

### 3. Theorems & Postconditions (定理と事後条件)
(ここに実行後に保証される状態や不変条件をOxiLeanの証明仕様として記述する)
```

## 適用場面
- 複雑なビジネスロジックやセキュリティ境界（GigEngine, 決済エスクロー, CSAMガードなど）の設計時。
- 新しい機能の開発フェーズに移行する前の、Phase 1（脳と盾の分離）に基づく設計プロセスとして実行する。
