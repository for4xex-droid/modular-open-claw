# /deep-scan - ディープスキャン・コマンド実行プラン

このワークフローは、巨大なプロジェクト全域をコンテキストに過不足なく読み込ませ、セキュリティ、要件（Project NURTURE 等）、そしてアーキテクチャのギャップを最新の状態でスキャンするために設計されています。

## 目的
人間の目とLLMのコンテキスト制限（Token Limit）を突破するため、専用スクリプトによる静的解析結果と、自動同期されたアーキテクチャ定義を用いて俯瞰的な監査を行います。

## 実行手順

### Step 1: ディープスキャンの実行
// turbo
セグメント化されたディープスキャンを一括実行します。（ASTパーサやTaintスキャナは廃止され、このスクリプトに統合されました）
```bash
bash scripts/deep-scan.sh
```

### Step 2: アーキテクチャ定義の読み込み
システム全体の最新の構造を把握するため、自動生成されたマニフェストを読み込みます。

```bash
# ツール (view_file) で読み込み
# ARCHITECTURE.md（リポジトリルート。scripts/generate_architecture.py により自動生成）
```

### Step 3: レポート生成
エージェントは読み込んだ `deep-scan.sh` の標準出力と `ARCHITECTURE.md` から、以下について分析・レポートを行います：

1. **実装済みの主要構造・APIエンドポイントの総覧**
2. **Project NURTURE 要件に対する「不足機能（Gaps）」の特定**
3. **セキュリティチェック** (Type-Driven Securityの適用漏れ、環境変数の不整合など)

### 出力フォーマット例
```markdown
# 📡 Aiome Deep Scan レポート
- **スキャン対象**: {アプリ数} Apps, {ライブラリ数} Libs
- **実装状況**:
  - `StructName` は存在しますが、要件で定義された `CapabilityX` に対応するエンドポイントが不足しています。
- **推奨アクション**:
  1. `.env.example` の環境変数の補完
  2. `App/routes/y.rs` への `Authenticated` 型ガードの追加
```
